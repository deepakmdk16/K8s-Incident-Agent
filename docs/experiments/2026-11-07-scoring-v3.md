# Pre-registration — scoring v3: score the fix, not the sentence (STATUS 3.1)

Written BEFORE `evals/scoring_v3.py` was run over any bundle. The gold tree
(`evals/gold-v3/`) and the normalizer were authored from the scenarios and
are frozen at the commit that carries this section; the Result section below
is appended afterwards and reports whatever the run returned.

## What is being measured, and why it is a column and not a bar

The frozen scorer scores the failing resource and the mechanism SENTENCE
(`class_correct`). Twice (docs/failure-modes.md 2026-08-29, 2026-09-04) a
pooled number moved for reasons the rubric's vocabulary controlled, not the
agent's diagnosis. The solution arm's submission also names the FIX
(`remediation.field_path`, `current_value`, `required_value`, rendered into
the report by `solution/render.py`). The v3 column asks the question the
sentence rubric cannot: **did the agent name the right field, and the right
value?**

It is **additive and diagnostic**:

- The frozen metric, case set, `gold.json`, `scoring.py`, `scoring_v2.py` and
  every committed bundle stay byte-identical. v1's `root_cause_correct` /
  `class_correct` are read from `rows.jsonl`, never recomputed.
- It is reported beside the frozen number, never pooled with it, and sets no
  acceptance threshold. The decision doc's primary metric is unchanged.
- Arms whose contract does not carry the fields (baseline, rules) report
  **n/a**, never 0. Making the baseline emit the fields is a separate,
  disclosed contract decision and is NOT part of this slice.

## Instrument (frozen at this commit)

- Gold: `evals/gold-v3/<case_id>.json`, 15 files, schema and authoring rule
  in `evals/gold-v3/README.md`. 10 cases pin a value; 5 are open (sizes,
  replica counts, image references, URLs — gold's example is one choice among
  many), so `fix_value_correct` and `both_correct` are over the pinned rows
  only.
- Matching: normalized exact match (README "Matching"). No fixture lookup;
  name-form aliases are authored into the gold where the fixture makes them
  unambiguous.
- Accepted submission: the LAST `submit_answer` call in a row's
  `transcript.jsonl` (`solution/agent.py` breaks on the first accepted
  submit), none when `metrics.salvaged` is true or `error` is set — that row
  scores `no_submission`.
- Disclosure: before the gold was authored, exactly one submission had been
  looked at while learning the transcript format (frozen bundle, run1,
  `t1-crashloop-missing-env`: `field_path`
  `spec.template.spec.containers[name=worker].env`, `required_value` a
  free-text env block). It told me the name form exists and that
  "add an env var" values are prose; both were already in the plan. No other
  submission was read before this section was committed.

`fix_value_correct` and `both_correct` k/m over rows whose gold pins a value;
